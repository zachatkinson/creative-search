## The seven dimensions

**DRY and SOLID.** The count stays in `Destination`, the one place that works out where a query lands (D-145); the lookup read is a repository's, as every statement is. The term rule reuses `TermMatch::firmIn()`, the same rule the products follow (D-146).

**Anti-patterns.** WooCommerce's `Filterer` is internal and missing from the stubs, so it is mirrored rather than called; the mirror covers the two clause shapes the router sends (one value, an "or" list), and the test compares the count with the `Filterer`'s own clause so a change in WooCommerce shows. The table is read only when WooCommerce reads it.

**Security.** One new statement, prepared: the table by `%i`, the term ids as integers through `ints()`, `in_stock` by `%d` (SECURITY.md, v1.6.4). WooCommerce's filter is applied with its own default, as its listing applies it.

**Accessibility.** No markup changed.

**Internationalisation.** No new strings; the POT's references were regenerated.

**Testing.**
- Integration: `RoutingTest::test_see_all_leaves_out_a_product_whose_size_is_sold_out` builds a variable deck whose 8.25 is sold out and its 8.5 in stock, fills the lookup table, and holds the panel's count to WooCommerce's `Filterer` clause and to the router's logged count, in 8.25 and 8.5, and unchanged without the table. Without the fix it would count 4 where WooCommerce lists 2 (both decks sold out in 8.25 are in stock as products, so the visibility term doesn't drop them).
- Unit: `SearcherTest::test_a_term_reached_only_by_a_loose_candidate_in_its_description_is_not_offered`: "hody" offers no brand whose description says "body", still offers a tag whose description says "hoody", and "body" or "hzrd hody" still reach the brand.
- Infection on `Searcher.php`: 175 mutations, 100 % MSI.

**Performance.** The lookup read runs only for a landing with a filter, with the table in use and sold-out products hidden, once per cached panel answer and once per query sent on: one indexed `SELECT DISTINCT` per filtered taxonomy, its ids handed to the counting query. The term rule reads postings already loaded.
