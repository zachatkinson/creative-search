## The seven dimensions

**DRY and SOLID.** The category row goes through the same lookup as the picked scopes (`RankRepository::scopedObjects()`) and the same row builder; `CategoryScopes` stays the one place that decides which scopes the panel shows. The REST route resolves `here` with the same `CategoryScope::bySlug()` as `cat`. The ranking change stays inside the one statement builder; `scoreTables()` replaces `phraseTables()` rather than adding a second path, so one- and many-word queries share it.

**Anti-patterns.** No new query on the search path: the category row adds one primary-key lookup on `term_relationships`, and only when `here` is sent. The suggestion cache key carries `here`, so a category page never reads another page's answer. `STRAIGHT_JOIN` is used only where the plan is known to be right (the candidates are the smallest table by construction), and the rule that turns it on is measured, not a guess.

**Security.** `here` is validated as a slug (`bad/slug` is a 400) and resolved to a term before use; the SQL takes term-taxonomy ids as integers through `prepare()`. The overrides change development tools only; the zip's files are byte-identical.

**Accessibility.** One control fewer on category pages. The scope row is an option like the others, reached by arrowing from the field and announced by the live region; axe is clean on the panel with it (`scope.spec.ts`). A11Y.md's manual step 15g is rewritten for the row. The manual screen-reader pass is still not run.

**Internationalisation.** "Only in %s" removed; one new string (the REST argument's description), translated in `fr_CA`. The row reuses the existing "%1$s in %2$s" string.

**Testing.** Integration: `ScopeTest` covers the form with no checkbox and the category in its context, `here` offering Decks first with its URL, Apparel, a category with no match offering nothing, `suggest_scopes` off, and a bad slug. `RankParityTest` adds which word leads ("kazumi deck" leads with word 0, "deck kazumi" with word 1), no lead for two common words or one word, the key lookup in the join, and the same ranking as PHP in each case; the parity over the golden set and 240 generated queries holds the merged score tables. JS: the view sends `here` on a category page and never `cat`. Browser: `scope.spec.ts` on Storefront's sidebar form: no checkbox, the T-shirt still suggested on Decks, "kazumi in Decks" the first scope row, choosing it lands on the Decks-only results, Enter searches the shop.

**Performance.** See the gates: cold p95 roughly halved at 10,000 products, the worst query five times faster. What is left is the single-common-word statement (16 ms) and the document count for N (3.3 ms), which a `(generation, lang, type)` key would remove; that is a schema change and waits for Zach (D-132).

## Found and fixed during the gates

- **Two of D-088's ignore patterns went stale** with the rewrite (`ph.q` became `s.q`; `$found = false` is gone). Updated, so the ignores still cover only what D-088 lists.
- **The first mutation run of the new plan** left 18 escaped, all plan-only (the answer is the same whichever path runs). The ones a test could hold, which word leads and when, now are (`RankParityTest`); the frequency sums, the empty-token test and the two tie boundaries (`<` against `<=`) are ignored by line with the reason. `--mutators=` on the command line drops the config's ignores, so the check ran on a copy of the config with only its named mutators on.
- **The browser run after restoring the dev site** failed six tests: the 10,000-product loader was still writing index rows when the backup was imported. Imported again once it had exited; all six pass, and the full run is clean.
