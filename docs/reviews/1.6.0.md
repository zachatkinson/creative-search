## The seven dimensions

**DRY and SOLID.** The cap lives in one function, `budget()`, which now returns each group's count from one fill order instead of four hand-tuned limits; `showAnswer()` only slices. "Matches the title" is one pure rule in the Domain (`TitleMatch::covers()`), fed by the same `fieldsOf()` read the "Matches SKU" line uses (D-105), widened by a kind parameter rather than copied. Stock-first is one flag carried by the existing options and plan objects to the two places an order is made (the SQL statement and `Hit`), so the panel, the results page and `/search` cannot disagree. Who stays out of the log is one method, `SearchLog::ignored()`, asked by both the search log and the clicks.

**Anti-patterns.** No setting is read inside the Domain: `in_stock_first` is read once in `SearchService::options()`. The cap is applied in the browser because "a phone" is the browser's media query (the brief's definition); the answer from `/suggest` stays the same for both widths and cached once. The confirmation for Clear analytics is a page state, not a `confirm()` dialog. Hooks hold no logic: the Plugins screen link is `AdminPage::actionLinks()`.

**Security.** Clear analytics is a POST with its own nonce and `manage_woocommerce`, reached only from a confirmation step; the GET that shows the step changes nothing. The staff check reads the logged-in cookie with `wp_validate_auth_cookie()` because the panel's REST calls carry no nonce (kept so a cached page still searches); it can only leave a row out, never grant anything, so no nonce is needed, and a forged cookie is treated as a shopper (tested). The test header is compared to an exact `"1"` and never stored or printed. `DELETE FROM` goes through `$wpdb->prepare()` in the repository. The Settings link is shown only to users who can open the screen.

**Accessibility.** The panel's rows, roles and live-region count are unchanged; fewer rows only shorten it. axe runs on the capped panel on both themes and all five projects. The new Tools and Boosts rows use the existing labelled patterns, with `aria-describedby` on their descriptions. The confirmation is a labelled group (`role="group"`, `aria-labelledby` the section heading) with a real button and a Cancel link, reachable by keyboard with no script.

**Internationalisation.** Every new string is in the text domain, plurals through `_n()` (the counts in the confirmation, the notice and the CLI question, rewritten from a two-number sentence that read "1 logged searches"), no concatenated sentences; the editor's two new labels reach the script translations JSON. Canadian French for all 23 new entries, with the catalogue's non-breaking spaces before colons and inside « ».

**Testing.** JS: the cap at 8 and 5, a raised cap, the brief's "hood" answer on both widths, pages last, pages off a phone unless allowed. Unit: `TitleMatch` cases; Searcher tests where a better-matching sold-out product and a weaker in-stock one flip with the setting on and stay with it off (the brief's done-when), also across merged phrase-synonym forms; settings defaults and ranges. Integration: the block and shortcode caps; pages by title in the panel and by content on the results page; `StockFirstTest` through the SQL statement on the panel, the results page and `/search`, backorder counted as buyable, a pinned sold-out product kept first; `AnalyticsLaunchTest` for staff by role and by cookie, the header, the filter, clicks, the clear confirmation and action, the CLI and the Plugins link. Browser: the cap on every project, with axe.

**Performance.** The cap renders fewer rows. Pages in the panel now rank the first 10 content documents instead of 2 and read their name-field postings in one keyed query (only when posts or pages are indexed, and cached with the answer). Stock-first adds one leading column to the existing `ORDER BY` over the already-scored candidates; no new join or scan. The log gate costs one cookie check for signed-in visitors only.

## Found during the work

- **The block's attribute defaults are read when the block registers.** A test that changes the settings and then renders a block without attributes still sees the old defaults; the shortcode reads them per render. This is the existing behaviour for `limit` too and is right for a real request.
- **A verify run hid a failing unit test.** `composer test:coverage` writes the coverage report even when a test fails, and the floor script read it, so the floor passed over a broken test edited by a script of mine. Caught by Infection's initial run before the commit; every later gate was run with its exit code checked.
