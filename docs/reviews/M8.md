## The seven dimensions

**DRY and SOLID.** The language logic stays in `Index\Languages` (one `siteCode()` for the index, the query and the CLI); term counts in `TermReader::count()`; the French run reuses the shared axe helper, which gains one `exempt` parameter rather than a second helper. The matrix's switches live in one place (`tools/integration.sh` and the bootstrap), so a leg runs the same way locally and in CI.

**Anti-patterns.** Nothing hooks translations that WordPress already loads (no `load_plugin_textdomain()`, D-076). No multilingual plugin is installed to test French; a must-use fixture does what skatehouse-core will do (D-080). The one axe exemption is scoped to one rule in one state and argued (D-079), not a blanket disable.

**Security.** No new route, handler or input. The language fallback reads the site's setting, not the visitor's locale (D-076). Translated strings go through the same escaping at the sink, and the i18n check fails a translation whose placeholders differ from the source's. A review finding moved one escape back to the sink (BoostsTab). FiboSearch was installed in wp-env for the benchmark and removed with its options. `composer audit` and `npm audit --omit=dev` are clean.

**Accessibility.** axe on the French panel, results, no-results, every admin tab and the product panel, on three engines and two widths. The run found and fixed three things: Up from the field went to the wrong row, "See all 1 results", and parent categories announced as "(0)". The manual screen-reader pass is **not run** (docs/A11Y.md).

**Internationalisation.** 299 strings, all translated into Canadian French with French typography (no-break space before colons, guillemets). Plurals through `_n()`, including the counts the review found without it; label-and-number forms where several counts share a sentence. The scripts' strings ship as JSON named after the built files (D-084). `composer i18n:check` keeps the POT current and the translation complete.

**Testing.** The French browser spec (14 tests, 70 runs across the five browser projects), integration tests for the site language, the term counts and their re-queue on a visibility change, the translations in PHP and both scripts, the two-form "See all", and the query plans; JS unit tests for the Up key and the singular row. `src/Domain` changed in one place (D-085: the searcher passes the query's key to `IndexStore::documents()`), so Infection was re-run on `Searcher.php`: 156 mutants, all killed (100 %). The rest of the changed code is in `src/Index`, `src/Hooks`, `src/Block` and `src/Repository`, which the integration suite covers and Infection's unit run does not reach.

**Performance.** Every search statement has a key (`QueriesExplainTest`). The 10,000-product budgets were measured for the first time: the reindex passed (99.9 s against 300 s), and the request budgets failed (`/suggest` cold 214 ms, `/search` 209 ms, memory 14.5 MB). Two exact read fixes (D-085) brought the times within budget: `/suggest` cold 81.4 ms, warm 0.4 ms, `/search` 76.9 ms. **Memory is 8.41 MB against 4 MB and fails.** Meeting it needs the spec's in-database scoring or a compact postings structure; that is Zach's choice, and the benchmark keeps asserting 4 MB so CI stays honest. Whole-request time per keystroke is about 100 ms on wp-env, mostly WordPress's bootstrap; a lighter request path (FiboSearch Pro documents SHORTINIT) is a follow-up after 1.0.
