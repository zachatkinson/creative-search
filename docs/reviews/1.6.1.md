# 1.6.1 review: updates through wp-admin, from the agency's releases

Built 3 November 2026 on the branch `release-1.6.1`, after 1.6.0 shipped, when Zach asked whether any brief was left open. Creative Search was the one agency plugin not wired into `zachatkinson/creative-releases`: the spec's "no outbound requests" (gate 5) had kept the updater out, so every fix needed a zip uploaded to each shop by hand. Zach chose to port the sibling plugins' updater ("1."). One commit. No schema change, no dependency, no public hook renamed, no floor moved; no index rebuild is owed.

## The seven dimensions

**DRY and SOLID.** The code is the agency's one updater, ported with names changed, so a fix to it is the same fix in every plugin. The manifest source is an interface, so the tests give the Updater a manifest without a request. The manifest's cache key is one constant, used by the source, the uninstaller and the test.

**Anti-patterns.** Hooks hold no logic: `register()` adds four filters, and each one calls a method. The search path does not reach the updater. The manifest is read only when WordPress checks for updates, never on a shopper's page.

**Security.** There is one fixed https address, read through `wp_safe_remote_get()`, and no input reaches it. The user agent leaves out the site address. The package is accepted only from `github.com` over https, and only when its SHA-256 matches the manifest; a mismatch is deleted and refused (tested). Nothing from the manifest is executed, and its changelog is escaped in the details popup (tested). The off switch removes every hook. Gate 5 still fails on any other outbound call. The force-check reads `$_GET['force-check']` only to clear a cache, as core does.

**Accessibility.** No front-end change. The details popup is WordPress's own.

**Internationalisation.** The checksum error is in the text domain and translated into Canadian French. The popup's sections come from the manifest, in English, like the sibling plugins'.

**Testing.**
- Unit: `ManifestTest` covers good and bad manifests: the version, the host, a lookalike host, a non-zip, the hash, the types and the optional fields.
- Integration: `UpdaterTest` checks that the header and the filter host agree, that core sees the update and leaves other plugins alone, that the popup escapes the changelog, the SHA-256 check (a mismatch deleted), the off switch, and that the HTTP source caches a failure and sends `Creative Search/<version>`.
- `UninstallTest` now checks that the site transient is gone, and that the uninstall.php fallback deletes it.

**Performance.** At most one request every 12 hours, during WordPress's own update check, with a 10-second timeout. A failure is cached for an hour, so a GitHub outage costs one timeout an hour on wp-admin's update screens and nothing on the shop.

## Found during the work

- **A custom header on every origin moved the panel.** With Playwright's `extraHTTPHeaders` the theme's Google Fonts requests failed their CORS preflight. The fallback font moved the field, and the panel's height budget dropped a scope row. The fixture sends the header to the shop only (D-141).

- **The site transient was outside uninstall.** The prefix delete covers `_transient_csearch_%`, but the manifest uses a site transient (`_site_transient_…`, or the network's sitemeta). The transient is now deleted by name, once for the network.
- **Plugin Check's errors never failed the run.** `wp plugin check` exits 0 with errors, so "zero errors" was checked by reading the output. The wrapper makes the check strict.
