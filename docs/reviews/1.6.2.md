## The seven dimensions

**DRY and SOLID.** "Found only by its description" is one flag on the score, decided by the same rule in the PHP Scorer and in the statement and held to it by `RankParityTest`'s new round. The panel, the results page and `/search` all read it through `Hit::stockFirst()` or the one `ORDER BY`. The description fields are one constant (`Fields::DESCRIPTIONS`) that both rankers use. The page asked for is a fill step in `budget()`, the one place the panel's room is shared out. The updater's new check sits behind the existing `ManifestSource` interface, so tests still need no network.

**Anti-patterns.** No setting is read in the Domain. The panel reads no rule of its own about descriptions: it uses the server's `described`. The split happens only when there is a page to place, so an answer without one renders as before. `verify()` refuses rather than guessing when the manifest can't vouch for a package.

**Security.** A package for this plugin can no longer reach WordPress's installer unchecked: only a package the manifest names, with a matching SHA-256, is installed. Every other plugin's package is left to core (tested). The manifest is re-read once per attempt, through the same `wp_safe_remote_get()` to the same fixed address, so gate 5 is unchanged. The new `WP_Error` message is translated and carries no address.

**Accessibility.** The panel's rows, roles and live-region count are unchanged. A page row keeps its "Pages and posts" heading wherever it sits, and the other pages show the heading only when the page asked for isn't shown. The handoff browser test runs axe on the panel with the page row, on a phone too.

**Internationalisation.** The new help text and the updater's new error are in the text domain and translated into Canadian French, with the catalogue's "UGS" for SKU and a non-breaking space before the colon.

**Testing.**
- Unit: a sold-out name match stays above an in-stock description match with the setting on (the brief's first case). Of two name matches, the in-stock one comes first, and the description match comes after both (the second case). `Score`'s default.
- Integration: `StockFirstTest` gains a description-only product on all three surfaces, and checks the panel's `described`. `RankParityTest` gains an in-stock-first round and compares the flag. `UpdaterTest` adds the brief's four cases (a package the manifest no longer names, an unreadable manifest, a match, a mismatched hash), the package core offers for this plugin, and the fresh read replacing the cache.
- JS: "size guide" with only description matches, the page between named and described products (desktop and phone), "returns" on a phone, the page at the cap, and "hood" with no page.
- Browser: the size guide page on desktop and phone, with axe.

**Performance.** One more aggregate in the statement's `s` step, over rows it already reads, and one leading `ORDER BY` column when the setting is on; no new join. The panel's split is a filter over at most the panel's limit. The manifest is re-read only when an install meets a package the cache doesn't name.

## Found during the work

- **The 1.6.0 test that encoded the gap.** `SearcherTest`'s "the order flips" asserted exactly what the brief now calls wrong: an in-stock hoodie found by its description jumping over a sold-out deck named for the search. It is rewritten to the new rule.
- **A failing JS test hid the next ones.** The panel-fitting test stops before it restores the window's height and animation-frame mocks, so ten later tests failed too. Rewriting the page tests fixed all of them; the cascade is a test-isolation weakness worth an `afterEach` later.
