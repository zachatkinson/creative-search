# 1.6.5 review: no empty page from a size search

Built 5 November 2026 on the branch `release-1.6.5` from Zach's brief (docs/BRIEF-creative-search-1.6.5.md), from the check of 1.6.4 on the Skatehouse demo: "9 deck" opened Decks filtered to 9.00″ ("No products were found matching your selection." twice), its panel promised six "In stock" decks that "Match Width: 9.00″", and "9 hoodie" opened an empty search filtered to a width hoodies don't have. One commit per item, then the release commit. No schema change, no dependency, no public hook renamed, no setting added, no floor moved; no index rebuild is owed.

## Spec review

An independent spec review (the `spec-reviewer` agent, with throwaway probes in wp-env) found 1 blocker, 4 should-fix and 7 minor; all but one are fixed in the review commit:

- **Blocker, fixed.** "Matches Width: 9.00″" still showed on sold-out sizes with sold-out products hidden: WooCommerce then leaves sold-out variations out of a product's visible children, so the product's own value (no key, no slug) was the one matched and skipped the stock check. `MatchDetails` now finds such a value by its attribute's label and term name. The test had created its decks before hiding sold-out products; it now sets the demo's configuration first, and fails without the fix.
- **Should-fix, fixed.** A closest value could come from a draft or hidden product on the shop page (now read among the products the landing lists; tested); a landing with every value left out and no category lost "Search all products for …" (now kept, without a "Showing" lead; tested); "See all" is now held to the landed page's own `found_posts` for seven queries; the panel's cache kind is `suggest2` and its key carries the two stock options.
- **Minor, fixed.** Closest links built from the page's first page; "Closest in stock:" through `_n()` (French plural); the Skatehouse "9 hoodie" check asserts it lists products and "philly 8.5" its count; HOOKS.md's `csearch_query_filters` says it can run twice; `leaveOut()` returns the kept count instead of counting again; the text helpers moved to `Search\ValueText`.
- **Minor, left.** The signed arguments aren't tied to the page they were made for, as `csearch_from` never was; pasted elsewhere they can only show text the site generated (D-154.6). `lists()` repeats the lookup read the count made, once per uncached panel answer with an applied value.

## The seven dimensions

**DRY and SOLID.** Where a query lands stays worked out once, in `Destination`, for the redirect, the panel's count, the panel's products and the log; the landing is now a value object (`Landing`) rather than an array whose shape three callers read. The landing's listing is one query builder (`Destination::query()`) used to count, to list the closest values' products and to limit the panel. The line's wording is one small class (`Search\ValueText`) the page and the panel both use, so the panel's service doesn't lean on the results view; its attribute-and-values wording is shared with D-101's "Showing products with" line. The stock reads are repository methods beside D-151's.

**Anti-patterns.** No product object is loaded on the search path: stock per value comes from WooCommerce's lookup table, the one place it is kept per term. The Domain stays free of WordPress: `MatchExplainer` only passes the matched fact's key and slug on, and the stock rule lives in `MatchDetails`. The item-3 loop ends: each pass either finds every named attribute carried or adds at least one to the words, and there are finitely many.

**Security.** Four new statements, each prepared (SECURITY.md, v1.6.5). The two new landing arguments are covered by the same `wp_hash()` signature as `csearch_from`; a query with neither signs exactly as before, so links made by 1.6.4 still work; a forged or edited value shows nothing (tested). The values are parsed back to existing `pa_` taxonomies and `sanitize_title()` slugs; every printed string is escaped where it is built.

**Accessibility.** The panel's line is a status paragraph outside the listbox (not an option) and is read in the live region after the count (JS and browser tests). On the page, "Closest in stock:" leads a list of links whose text names the attribute ("Width 8.75″"), so each reads alone (WCAG 2.4.4); a sentence with inline links failed axe's `link-in-text-block` on Storefront, which doesn't underline links, so the list follows the no-results page's "Try one word:" pattern. axe passes on the landing page and the open panel on Twenty Twenty-Five and Storefront.

**Internationalisation.** Two new strings ("Nothing in %s is in stock right now." and "Closest in stock:", the latter with a plural for French), both translated; the attribute and value names come from WooCommerce's labels and terms. Only fr_CA ships in `languages/`; the brief's "all four languages" has nothing more to translate here.

**Testing.**
- Integration, `UnstockedTest` (new): three variable decks over six widths with sold-out variations, a second attribute (Concave), the lookup table on and sold-out products hidden. "9 deck" lands on Decks without the size, with `csearch_near` 8.75 only, logs 0, and "See all" counts Decks; the page's lines and order; the closest link lands on Decks in 8.75 with D-102's line; "7.75 deck" offers 8.0 alone, "8.5 deck" both sides, lower first; "8.25 deck" still filters; "steep 9 deck" keeps Steep and drops 9.0, "mellow 8.75 deck" drops both; forged and unsigned values are ignored; shown sold-out sizes still apply; the panel's line, its total, no "Matches Width: 9.0" (checked to fail with the stock check off), only Alpha and Bravo for "8.25 deck" and Charlie back without the lookup table; "9 hoodie" has no width filter and its results list the hoodie.
- `RoutingTest`: the "sold out and hidden" case now expects Decks without the size, logged as 0.
- `SkatehouseTest` (group `skatehouse`, needs the export): "9 deck", "9 inch deck", "7.75 deck" land on Decks without a filter and log 0; "7.75 deck" offers 8.00; "9 hoodie" has no filter; "8.25 deck" (88) and "philly 8.5" as in 1.6.4. Not run here: the export isn't on this machine.
- Unit: `MatchExplainerTest` checks the new key and slug and `withoutReason()`. JS: the line, the live region, "See all" and clearing. Browser: the landing page's lines, the closest link, the panel's line and live region, axe, on both themes.

**Performance.** A query that names no value costs what it did. One that does costs one `LIMIT 1` read per attribute named (item 3). Only when the landing would be empty: one count without the values, one per value when there are several, and on the redirect one read of the landing's products and one of their values in stock. The panel adds one read of the shown products' in-stock values when one matched by an attribute (cached with the match details), and, when the landing applies a value, the landing's query limited to the panel's candidates. All once per cached panel answer.
