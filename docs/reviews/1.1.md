## The seven dimensions

**DRY and SOLID.** One tokenizer still serves the index, the parser, the results hook and the CLI; the size rules are one function (`Tokenizer::units()`) both sides call. Posts and pages reuse the Searcher with a kind, not a second searcher; `ContentReader` owns what a post becomes and whether it is indexed, and `ContentReader::parentTitle()` is the one place a parent's title is read, for the index and the answer alike. The dialog is the same form in a `<dialog>`, one markup path (`SearchForm`) for the block, the shortcode and the widget. The no-results links and the two benchmark tests were each folded into one.

**Anti-patterns.** No new table, column or option for the pages (kind 2 in the existing column, approved). The page links are page pickers, not free URLs. The panel's no-scroll rule is a row budget plus a measured trim, not a CSS clip. The dialog uses the platform's `showModal()` for inertness and focus, not a script focus trap.

**Security.** The exclusion box checks its nonce and `edit_post`, skips revisions and autosaves, and escapes its output. The link settings are page ids, rendered only for a published page; text is sanitised and capped at 120 characters. The review found a private or protected parent page's title indexed and sent to anonymous callers ("Private: …"); it is now used only for a published parent with no password, tested. Row classes from other plugins pass through `sanitize_html_class()`, at most 8. Nothing per user or nonce is in the block, so a public page cache cannot leak one visitor's markup to another.

**Accessibility.** D-079's axe exemption is gone: the panel no longer scrolls (D-092). The dialog is a native modal with an accessible name, `aria-haspopup`, focus into the field within the click and back to the button on close; Escape closes the panel first, then the dialog; Back closes it. The group heading over pages is `aria-hidden` (a listbox holds options only); each row's name says "Page" or "Post". The completions are marked by weight, not colour. Two faults found by the browser tests were fixed: the field pointing at a row the trim removed (axe `aria-valid-attr-value`) and the panel measured before its rows and font, ending below the screen. The manual screen-reader pass is still **not run** (A11Y.md, steps 1 to 15b).

**Internationalisation.** 32 new strings, all in Canadian French with French typography; plurals through `_n()` (`%1$s (%2$s result)`, the CLI summary); the group heading chosen by what is on, not built from parts; French decimal commas and inches (`8,25 po`) read as sizes.

**Testing.** New: ContentTest (19 tests), the dialog, the page-cache render and the shortcode in BlockTest, row classes and the cache actions in ApiTest, the owed rebuild in ReindexTest; unit tables for every size form in the handoff and the golden test that each spelling finds the same products; RankPlan name keys; JS tests for the trim and the dialog; `tests/e2e/handoff.spec.ts` on five browser projects. The handoff's page queries (returns, shipping, size guide, wheel guide, contact, track order, dealer, pre-book) are in ContentTest. Its grip queries (`9x33 grip`) cannot be checked against the generated catalogue, which has no grip sheets in those sizes; they belong to 1.2's run on a copy of Skatehouse (item 11).

**Performance.** With pages and posts on, each `/suggest` miss makes a second pass over kind 2. At 300 products it costs about 2 ms of the cold answer (4.4 ms at 1.0, 6.5 ms now). The review found the rows' parent titles read one query each; the posts and their parents now load in two queries in all. The benchmark now measures the API with pages and posts on. It also loads the catalogue once for both measurements, with each phase's time in the log, because PR #1's 10,000-product CI job spent over an hour loading the catalogue twice.
