# 1.6.6 review: a value filters only where the real matches carry it

Built 6 November 2026 on the branch `release-1.6.6` from Zach's brief (docs/BRIEF-creative-search-1.6.6.md), from the check of 1.6.5 on the Skatehouse demo: "9 hoodie" still said "Nothing in Width 9.00″ is in stock right now." and offered a deck width, because three decks mention a hoodie in their descriptions; and "Closest in stock:" had a plain space before its French colon. One commit per item, the review fixes, then the release commit. No schema change, no dependency, no public hook renamed, no setting added, no floor moved; no index rebuild is owed.

## Spec review

An independent spec review (the `spec-reviewer` agent) found 1 blocker, 3 should-fix and 5 minor; all fixed:

- **Blocker, fixed.** The first name check dropped a filter that listed products: on the test store "9 boards" lost Boards in 9.0 because a Cloud 9 Board without 9.0 was among the boards, breaking "a query whose strong matches carry the attribute still applies it". The name check now runs only when the value would leave the page listing nothing (D-154's case, the one it was for); "9 boards" is tested.
- **Should-fix, fixed.** The name check covered every value word, not only numbers, while D-157 spoke of numbers: it is now numbers only, as the brief asked, and the record says why. It read the whole store's matches on a search kept to a category: now within the category. The 1.6.6 review and SECURITY.md line were missing: added.
- **Minor, fixed.** D-157 now states the name check's full cost; the French check also refuses a colon with no space (not in an address or a time); the hidden-product test asserts the exact landing; a test for a search kept to a category; the panel's cache kind bumped so a 1.6.5 answer with the old line isn't served.

## The seven dimensions

**DRY and SOLID.** Where a query lands is still worked out once, in `Destination`, for the redirect and the panel, so the panel follows the new decision with no code of its own. The description-only flag is D-142's, read where the products are ranked (`rankedIds()`), the same flag D-146 and D-147 use; `strong()` and `hidden()` are one small helper each, used by both the open and the kept-to-a-category landings. The PO reader moved to a functions-only file so the check and the unit test share it.

**Anti-patterns.** No product object is loaded: names come from the index's postings, terms from the term relationships. No threshold is tuned to a catalogue: the name scan reads the first ten strong matches, the same order of size as D-147's scope choice. No Skatehouse slug, name or word is in the code. The routing loop still ends: each pass adds at least one attribute to the words, and there are finitely many.

**Security.** One changed statement (`carries()`), prepared, its new value an integer; no new input or argument (SECURITY.md, v1.6.6).

**Accessibility.** No markup changed. The line that was wrong for "9 hoodie" no longer appears, in the panel's live region or on the page.

**Internationalisation.** Nine fr_CA strings respaced; a check that runs in CI and in the unit suite keeps every fr_CA string to the locale's colon and guillemet spacing. Only fr_CA ships; another locale gets its own rules when it ships (D-158).

**Testing.**
- Integration, `StrongValueTest` (new, generic store: apparel in sizes, boards in widths, one board's description mentioning a pullover): "9 pullover" lands on the results for the words with no line, and the panel shows no line and counts that page; "9 stitched" (description matches only) filters as in 1.6.5; "8 board", "pro 9" and "9 boards" still filter; "cloud 9" is the board's name; a value only a hidden product has doesn't filter; a value only a sold-out product has gets D-154's line; a search kept to a category judges by its own matches. The three behaviour tests fail on 1.6.5's code.
- `SkatehouseTest` (group `skatehouse`, needs the export): "9 hoodie" now also checks the panel's line and count. Not run here: the export isn't on this machine.
- `UnstockedTest`, `RoutingTest`, `PanelTest`: unchanged and passing ("8.25 deck", "9 deck", "7.75 deck" and the 1.6.3 cases).
- Unit, `I18nTypographyTest` (new): every shipped PO, the fixed strings, seven strings it must refuse and four it must pass; fails on the old PO.

**Performance.** A query that names no value costs what it did. One that does now reads the other words' search with its description flag (already cached with it). Only when a number's value would list nothing: one count, one cached search of the whole query, one read of name postings and up to ten reads of product terms. Budgets at 300 products as in 1.6.5.
