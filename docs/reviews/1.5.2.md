# 1.5.2 review: the block's buttons keep their own look inside a theme's styles

Built 27 October 2026 on the branch `release-1.5.2`, a patch release after 1.5.1. Zach's report from the Skatehouse demo: once something is typed, hovering the X shows a black block. Found with Playwright on the live page: Kadence's `button:hover` (0,1,1) gave the button its dark hover background over the plugin's `background: transparent` (0,1,0), and the site's `.wp-block-kadence-header .csearch-clear:hover { color: var(--global-palette3) }` made the X the same `#121212`. CSS only: no PHP or JS change, no schema change, no hook, setting or string, no floor moved, no dependency.

## What was built

| Item | What | Decision |
| --- | --- | --- |
| Button states | `:is(:hover, :focus, :active)` rules at 0,2,0 for `.csearch-clear`, `.csearch-submit`, `.csearch-open` and `.csearch-close`: the button's own colour and background (the submit's `--csearch-submit-*`), no border, no shadow, outline left to `:focus-visible` | D-134 |

## The seven dimensions

**DRY and SOLID.** One rule per button family, beside each family's base rule; the submit's state rule reads the same `--csearch-submit-*` hooks as its base (D-128), so the colour hooks stay the one way to recolour it.

**Anti-patterns.** No `!important`, and no heavier selector than needed: 0,2,0 beats the theme's `button:hover` and only ties with a site's `.site-header .csearch-submit`, which loads later and keeps winning. D-125's 0,4,0 would have turned Skatehouse's own submit background transparent on hover. Outline is not reset, so the focus ring is never lost to the new rules.

**Security.** CSS only; nothing reaches the server.

**Accessibility.** The X is visible on hover again (it disappeared into its background), and keyboard focus still shows the one `:focus-visible` ring with no theme background behind it, asserted from the keyboard on Chromium, Firefox and WebKit. The contrast of the X is the field's text colour on the field, as when it is not hovered.

**Internationalisation.** No string added or changed.

**Testing.** Two browser tests in `sticky.spec.ts` add Kadence's button rules, as `global.min.css` writes them, to the page:
- In the sticky header, the hovered X keeps the field's colour on no background with no shadow.
- The submit keeps a site's own header background and colour on hover.
- A site's own `.csearch-clear:hover` colour still wins.
- The X focused from the keyboard has no theme background and the plugin's solid focus ring.
- In Button mode the hovered open button keeps its colour on no background.

Both tests fail against 1.5.1 and pass on every project.

**Performance.** Four rules in the block stylesheet; no script, no layout change.

## Found during the work

- **The panel's add to cart was a suspect, not a case.** It has no background of its own, but it is a `<span>`, so theme button rules do not reach it; it is unchanged.
- **WebKit on macOS skips buttons with Tab.** The keyboard step presses Option+Tab there, as `admin.spec.ts` does.

## Not covered

- Themes other than Kadence-style `button:hover` rules; a theme selector heavier than 0,2,0 on buttons would still reach them (none known).
- The live Skatehouse page until 1.5.2 is installed there; until then the Additional CSS snippet given to Zach covers it.
