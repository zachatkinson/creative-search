## The seven dimensions

**DRY and SOLID.** Where a query lands is worked out once (`Destination`), for the redirect and for the panel's count; the router keeps only what is its own (the log, the target, leaving the page). "Loose" is one flag on `TermMatch`, set in one place (`Searcher::typoCandidates()`), and read by both rankers through the same rule (`TermMatch::firmIn()` in PHP, `lo`/`nd` in SQL), held together by `RankParityTest`. The description fields stay one constant. The scope's strong matches reuse D-142's `descriptionOnly`.

**Anti-patterns.** The SQL of a plan without a loose term is unchanged, column for column. The Domain reads no setting: the short-word rule is a constant and the synonyms are passed in. The panel's script gets one boolean (`scopesDescribed`) rather than a rule of its own.

**Security.** The new statement columns are integers through `$wpdb->prepare()`. The panel's count runs the router's own `WP_Query` with WooCommerce's sanitised slugs. `Updater::tested()` only changes the displayed and compared "Tested up to". The release workflow gains `actions: read` and keeps its token check (SECURITY.md, v1.6.3).

**Accessibility.** No markup changed. The panel's rows, roles and live count are as before; a description-built scope row still renders after the category row it gives way to.

**Internationalisation.** No new strings; the POT and fr_CA references were regenerated. The short-word rule counts letters (`mb_strlen`), so a four-letter Cyrillic word is short like a Latin one (tested).

**Testing.**
- Unit: the typo family (stem and synonym, the closest kept first, every member at the typo's weight and not loose), the loose flags (four letters vs six, a multi-byte word), a loose name match counting, a loose description-only match ranking last with and without in stock first, `Hit::compare()` and `Hit::stockFirst()` putting `looseOnly` first whatever the score.
- Integration: `RoutingTest` (See all equals the landing count for a category and size, a brand and size, a size alone; unchanged without a size, for a category alone, for a size no term has, and with no attribute filtered by), `CorrectionTest` ("hody" finds what "hoody" finds and counts the same, a short typo finds nothing through a description alone, "shipping" shows the page without the deck, in stock first within the corrected word), `StrongScopeTest` ("beanie" offers no Decks scope and keeps the Hats category row; all-description matches choose as before and say so), `UpdaterTest` (the branch rule, both surfaces), and `RankParityTest` with 40 typos of description words.
- JS: at a phone's cap of 5, a description-built scope gives way to the category row; a strong one keeps 1.6.2's place.

**Performance.** A query that names no filter adds its parse to an uncached panel answer; one that does adds the landing's search and one counting query, once per cached answer. The statement adds two integer columns and one filter only when a typo produced a loose term. The scope reads the same ten products' categories as before.

## Found during the work

- **The test catalogue couldn't tell the counts apart.** In it, "8.75 deck" found one product either way; a deck naming 8.75 in its description (as Skatehouse's do) makes the test fail on 1.6.2's count.
- **A stem is no loose match.** "tigerz" read as "tiger" brings "tigers" through the shared stem, so a product mentioning tigers is found as "tiger" typed would find it, which is correct; the loose-ranking test uses words with different stems ("plane", "plank").

## Spec review

The spec-reviewer found one blocker, five should-fix and five minor points.

- **B1, fixed.** The PHP ranker dropped a short typo's description postings for the whole query, the statement per word; a term another word also read lost its description match in PHP only. `Ranker::withoutDescriptions()` now works per word, and the parity test has queries that pair a typo with one of its words, plain and excluded.
- **S1, fixed.** A corrected word that is half of a phrase synonym ("tech dek") didn't reach the phrase; `Searcher::correctedForms()` parses the corrected query for its alternatives.
- **S2, fixed.** The family of a short typo (its stem, its synonyms) counted descriptions; every member now inherits the flag, and the statement treats a term without descriptions as loose.
- **S3, fixed.** With "Hide out of stock items" on, the panel counted sold-out products the page doesn't list; the count excludes them (tested).
- **S4, documented.** The owner's redirect, pins and the two-categories case keep 1.6.2's count (D-145).
- **S5, fixed.** The catalogue benchmark filters by width so the counting query is measured.
- **M1, M2, fixed.** `budget()` gives the category row its place only when there is a category row, and reads `described` from the first scope.
- **M3, documented.** `fit()` still drops rows from the end on a short viewport, so a described scope outlives the category row there (D-147.5).
- **M4, documented.** `Search\Destination` uses `Results\QueryRouter`'s static helpers while the router asks Destination; the namespaces already leaned on each other through `CategoryScopes` (D-145.2).
- **M5, accepted.** The phone cap with a described scope is checked by the JS test; the "beanie" catalogue in `StrongScopeTest` produces no scope at all, so no browser test covers it.
