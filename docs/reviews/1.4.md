# 1.4 review: Field mode in a sticky site header

Built 22 October 2026 on the branch `release-1.4`, after the 1.3 work (1.3.0 never shipped on its own; 1.4.0 carries both). It answers the Skatehouse brief "Field mode in a sticky site header", items 1 to 4, under D-125 to D-128. No schema change, no new dependency, no hook renamed, no floor moved. A new block attribute (`dimPage`) and shortcode attribute (`dim_page`), both per instance; no new setting. `csearch_dim_page` now receives the form's choice instead of `true`. Button mode is unchanged.

## What was built

| Brief item | What | Decision |
| --- | --- | --- |
| 1. Theme input styles | In Field mode the input is reset (background, border, radius, padding, shadow, outline, appearance) under a selector more specific than a theme's `input[type=search]` and `input:focus`, so the field draws the one box and the one focus ring; at least 16 px text on a touch screen so iOS does not zoom | D-125 |
| 2. Panel capping | In a fixed or sticky header, or on a touch screen, the panel is capped to the room left in the visual viewport and follows the keyboard opening and closing; within the cap it drops its last rows as D-092 does, and scrolls inside itself (`overscroll-behavior: contain`) only when two suggestions and "See all" do not fit, arrowing then scrolling the panel, not the page. `auto` flips above only when below is short and above is larger. A desktop page that scrolls keeps the natural height | D-126 |
| 3. Dimming | The block's "Dim the page behind the suggestions" toggle (Field mode only), `dim_page="no"` on the shortcode, the filter keeps the last word; inside a transformed header the layer is re-measured to cover the viewport | D-127 |
| 4. Colour hooks | Seven CSS custom properties for the field, the panel, the submit button and the focus ring, with today's look as the fallback; documented in HOOKS.md and the readme FAQ | D-128 |

The placement arithmetic is pure (`assets/src/block/placement.js`: `roomAround`, `place`, `scrollToRow`, `coverViewport`, `pinnedIn`) and tested without a browser; `view.js` measures and applies.

## The seven dimensions

**DRY and SOLID.** The placement rules live in one module of pure functions; `view.js` only measures the DOM and writes the context (`above`, `capped`, `panelMax`), which the server markup binds (`data-wp-class--is-capped`, `data-wp-style--max-height`). `dimPage` follows `mode`: read once in `FormOptions`, rendered in `SearchForm`, no caller reads it on its own. The colour hooks are fallbacks on the existing declarations, not a second stylesheet.

**Anti-patterns.** No PHP on the search path changed. The viewport listeners are added once per block (`priv.following`) and throttled to one update a frame; the panel is not measured while closed. No `!important` in the input reset: specificity alone, scoped to Field mode so Button mode's dialog is untouched.

**Security.** Nothing new reaches the server but a boolean attribute, coerced through `Settings::yesNo()`. The custom properties are the owner's CSS; the plugin outputs none of their values.

**Accessibility.** One focus indicator in the field (axe and a computed-style check in `sticky.spec.ts`); every row reachable in a capped panel on a phone, with the chosen row kept in view inside the panel; 16 px text on touch screens; the backdrop stays `aria-hidden`. The colour hooks move contrast to the owner, which the readme says. The manual screen-reader pass is still not run (A11Y.md, v1.4.0).

**Internationalisation.** One new string, the editor toggle's label, through the text domain and translated in `fr_CA`.

**Testing.** Unit: `placement.test.mjs` covers every branch of the placement rules; `view.test.mjs` adds a capped panel scrolling itself while the page stays put. Integration: `BlockTest` covers the default backdrop, `dimPage` false, `dim_page="no"`, the filter hearing the block's choice, and the uncapped starting context. Browser: `sticky.spec.ts` on a fixture page with a fixed, transformed header and clashing theme input CSS, on desktop and phone projects, covers the input reset and single focus ring, the capped panel following a viewport shrink, arrowing without page scroll, the natural height on a desktop, the backdrop covering the viewport and closing on a click, the no-dim page, and the colour hooks. `kadence.spec.ts` runs Kadence 1.5.2 itself, its main row sticky on desktop and phone with the form in the header's HTML element: the form stays at the top with the page scrolled 1,500 px, keeps its own look and single focus ring under Kadence's input styles, the panel stays on screen (capped on phones), the page dims over the viewport, axe is clean, and a click behind closes it without moving the page.

**Performance.** No server work added. In the browser, at most one placement a frame while the panel is open; nothing while it is closed. The style bundle grows by the reset and the fallbacks only.

## Found and fixed during the gates

- **The phone cap against D-092.** The first build scrolled a capped panel instead of dropping rows. The full browser run failed D-092's "no scrollbar" tests on both phone projects, and axe in Safari flagged the scrolling panel (`scrollable-region-focusable`). A capped panel now drops rows to its cap and scrolls only below the minimum; the chosen row is brought back into view after a drop. The sticky phone test passed 30 of 30 repeated runs after the fix, and failed 3 of 10 before the last part of it.
- **The cap and the border.** The panel overshot the visible viewport by its border (2 px); the cap now includes it.
- **CI on `main` after the 1.2 merge (red).** The oldest-pair job failed in the admin tests because wp-login.php's focus timer moved the typing between fields (its snapshot shows the password in the username field). One shared helper (`tests/e2e/support/login.ts`) now waits for that focus and checks both fields; the four specs that logged in on their own use it. The 10,000-product budget job failed on identical code (cold p95 78.6 ms on the pull request, 123.3 and 132.6 ms after); D-129 keeps the fastest of three timings per query.

## Also checked tonight

- **D-051 on Redis.** Redis 7.4 with Redis Object Cache on wp-env: answers shared between requests, a reindex moving them to the new generation, a synonym applied at once, the rate limit holding at the 31st request, and 78 shopper browser tests passing with Redis on. Removed after.
