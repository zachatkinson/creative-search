# Accessibility

Two layers: axe-core runs in CI on every screen and state (Playwright), and once per release a person who did not write the code runs the 15-minute script below with VoiceOver on Safari and NVDA on Firefox, and records the result here.

## Rules (spec: Quality bar → Accessibility)

The search bar is an APG list-autocomplete combobox: a label, `aria-expanded`, `aria-controls`, `aria-activedescendant`, options with accessible names ("KAZUMI Skate Deck, Dealer, $84.99, in stock"); keyboard parity (Down, Up, Enter, Escape, Home, End, Tab, Alt+Down); a polite live region that says how many suggestions; focus never trapped; 24 px targets (44 px rows on desktop, 48 px on a phone); visible focus; `prefers-reduced-motion` honoured; every admin screen keyboard-complete; colour never the only signal.

## The manual script (15 minutes)

Run on the shop with the block in the header and a catalogue of at least 300 products. Record pass/fail per step, the screen reader's words where they matter, and the date and tester.

### Shop

1. Load the shop's front page. Tab to the search field. Hear: the label, "combobox", "collapsed" (or equivalent).
2. Type `kaz`. Hear the live region: "6 suggestions" (or the count). The panel is visible under the field.
3. Press Down. Hear the first row: product name, price, stock. The row is visually highlighted. Focus stays in the field (the caret is still there).
4. Press Down five more times, then once more: the highlight wraps to the first row.
5. Press Up: the highlight wraps to the last row ("See all results for kaz").
5a. Press Escape, then Alt+Down to reopen the panel with nothing highlighted, then Up: the highlight goes straight to the last row.
6. Press Escape: the panel closes, the text stays. Press Escape again: the text clears.
7. Type `kazumi deck`, press Down twice, press Enter: the product page opens.
8. Go back. The field has the last query; press Alt+Down: the panel reopens with the last answer.
9. Type `snowboard`. Hear "No suggestions". The panel shows a no-results row.
10. Clear the field with the clear button (Tab to it, Enter). Hear the field is empty.
11. Type `deck` and press Enter without opening a row: the results page loads. Hear the result count ("23 results for deck") as the page's heading or first announcement.
12. On the results page, Tab to the sort menu: "Relevance" is the selected option; change it to "Price: low to high" with the keyboard; the list reorders.
13. Zoom to 200 %: the panel and the results stay usable, nothing overlaps.
14. Turn on reduced motion in the OS: the panel appears without a fade.
15. On a phone (or a 375 px viewport with touch): tap the field, type, tap a row. Rows are at least 48 px tall.

### Admin (keyboard only)

16. WooCommerce → Search → Analytics: Tab through the period selector, the chart (it has a text alternative), the tables (column and row headers are announced), the Explain and Export buttons.
17. Synonyms: add a synonym with the keyboard alone; hear the notice; delete it; hear the notice.
18. Boosts and exclusions: add a rule and a fallback product by SKU; hear the notice.
19. Tools: start a rebuild; the progress is announced (live region); Cancel is reachable.
20. Product edit screen: the Search panel's boost and exclude fields are labelled and in the tab order.

## v0.6.0 (the block and the results page)

**Automated:** axe-core (WCAG 2.0, 2.1 and 2.2 A and AA tags; serious and critical fail the build) on the block closed, open, with no suggestions and after an error, on Storefront's, Kadence's and Twenty Twenty-Five's results pages and their no-results state; chromium, Firefox and WebKit at desktop and phone widths: 85 runs green. The APG script steps 1 to 8 and 11 to 12 are automated in `tests/e2e/search-block.spec.ts` and `results.spec.ts` (the `aria-*` state after each key, the live region's words, focus kept in the field, Enter, Escape twice, Tab, Alt+Down, the results page's Relevance sort). One axe finding fixed on the way: options named by `aria-label` did not match their visible text (WCAG 2.5.3); they are now named by their text with visually hidden separators (D-064).

**Manual:** not run. The script above needs VoiceOver and NVDA and a person who did not write the code; it is milestone 8's (spec: "the manual accessibility pass").

## v0.7.0 (the admin)

**Automated:** axe-core, the same tags and threshold, on each of the four tabs of WooCommerce → Search, on the Synonyms tab with a row and a notice, on the Tools tab with a test search's explanation, and on the product editor's Search panel; chromium, Firefox and WebKit at desktop and phone widths: 40 runs green (`tests/e2e/admin.spec.ts`). Script steps 16, 17, 19 (the test search) and 20 are automated by keyboard alone: the focus is reached with Tab (Option+Tab on WebKit, as Safari's default skips links), a synonym is added, tested and deleted, a test search is run, an Analytics period is chosen by type-ahead, and the product's Search tab is opened with Enter. Every tab's visible inputs have ids for their labels and unique ids (an integration test renders each tab). One finding on the way: WooCommerce's product picker (selectWoo) fails axe (an unlabelled search field, `aria-expanded` on a role that does not allow it), so fallback products are chosen in a labelled SKU field (D-069).

**Manual:** not run; milestone 8's, with VoiceOver and NVDA.


## v1.0.0 (languages)

**Automated:** the same axe tags and threshold on the French shop and admin (`tests/e2e/french.spec.ts`), on Chromium, Firefox and WebKit at desktop and phone widths: the open suggestion panel in French with French prices, the French results page, its no-results state, and WooCommerce → Search in French. The French accessible names were checked: the French product name, the price as "84,99 $" and "En stock" for a product row, the live region's "N suggestions", and "Voir les N résultats pour …". `<html lang="fr-CA">` is set by WordPress from the locale, so screen readers switch voice.

**Found and fixed in this pass:**
- Up from the field with no suggestion chosen went to the second-to-last row. It now goes to the last, as the APG pattern expects; step 5a of the script now checks it.
- The panel's last row said "See all 1 results" (in French, "Voir les 1 résultats"). It now has a singular (D-077).
- A parent category was announced as "(0)" products (D-078).
- When nine rows overflow the panel, axe reports `scrollable-region-focusable`. In this pattern the options are reached by `aria-activedescendant` and scrolled into view by the arrow keys, which the test proves. That one rule is exempt for the open panel only (D-079).

**Manual:** **not run.** The 20-step script above needs VoiceOver on Safari and NVDA on Firefox, run by a person who did not write the code. It is the one part of milestone 8 that automation cannot do, and it needs Zach or a tester Zach chooses. When it is done, add a row to the record table with the date, the tester and the words heard, and file any failure as a bug against 1.0.x.
